# Desktop app

The servef desktop app shows the same UI in its own windows, one per project,
and notifies you when a branch switches, a commit lands, edits settle, or a
walkthrough is published. It talks to one long-lived servef daemon per user
over a private socket, so every window and `servef .` share the same server.

The app is a preview: macOS builds are not notarized and there is no
auto-update. Install a new version over the old one.

## Install

### Install script

macOS and Linux, no sudo:

```sh
curl -fsSL https://raw.githubusercontent.com/flexdinesh/servef/main/scripts/install-desktop.sh | sh
```

It installs the latest release's app and the `servef` CLI (in `~/.local/bin`,
or `~/bin` when that is on your `PATH`). Run it again to update; quit the app
first.

- macOS: `servef.app` goes to `/Applications` (or `~/Applications`). curl
  marks nothing as downloaded, so Gatekeeper does not block the first launch.
- Linux: the AppImage goes to `~/.local/share/servef-desktop/`, with a
  desktop entry that opens `servef://` links, an icon, and **Open in servef**
  in Dolphin and Nemo. If the AppImage does not start, install FUSE 2
  (`libfuse2`); the script says so when it cannot find it. It stops when the
  deb is installed.

To remove it, run
`curl -fsSL https://raw.githubusercontent.com/flexdinesh/servef/main/scripts/uninstall.sh | sh`
([Uninstall](#uninstall)).

### Packages

Download a package for your system from
[GitHub Releases](https://github.com/flexdinesh/servef/releases). `<version>`
omits the leading `v`; pick `arm64` or `amd64` for your CPU.

#### macOS

1. Download `servef-desktop_<version>_darwin_<arm64|amd64>.dmg` (or the
   `.zip`).
2. Drag **servef** to Applications.
3. The app is ad-hoc signed, not notarized, so Gatekeeper blocks the first
   launch. Right-click **servef** in Applications and choose **Open**, then
   confirm. Or clear the download quarantine once:

   ```sh
   xattr -dr com.apple.quarantine /Applications/servef.app
   ```

Installing the app registers `servef://` links with macOS.

#### Linux

Install the `.deb` (Debian, Ubuntu, and derivatives):

```sh
sudo apt install ./servef-desktop_<version>_linux_amd64.deb
```

It installs to `/opt/servef`, adds `servef-desktop` to `PATH`, and registers
`servef://` links through its desktop entry.

The AppImage runs without installing:

```sh
chmod +x servef-desktop_<version>_linux_amd64.AppImage
./servef-desktop_<version>_linux_amd64.AppImage
```

An AppImage registers `servef://` only through desktop integration (for
example AppImageLauncher, or the entry below). Without it, `servef .` cannot
find the app and serves in a browser instead. To register it yourself, keep
the AppImage where it is and create
`~/.local/share/applications/servef-desktop.desktop`:

```ini
[Desktop Entry]
Type=Application
Name=servef
Exec=/home/you/Applications/servef-desktop_<version>_linux_amd64.AppImage %U
MimeType=x-scheme-handler/servef;
Terminal=false
```

then run `update-desktop-database ~/.local/share/applications`.

The app bundles its own `servef` binary, so it needs no separate install. The
`servef` CLI ([Getting started](/docs/getting-started)) is what opens it from a
terminal.

## Window title bar

Windows draw their title bar in the current color theme, like VS Code. On
Windows and Linux the menu button at its left opens the app menu (File,
Edit, View, Window, Help); keyboard shortcuts work as before. A window
connected to an older servef over ssh shows no title band until that host
is upgraded.

## Open from a terminal

With the app installed:

```sh
servef .
```

servef checks the directory, starts the daemon if needed, adds the directory
to it, opens the project in the app, and exits. A window already showing the
project comes forward. `--no-open` prints the `servef://` link instead.

servef serves in a browser instead, as `servef browser` does, when:

- `--host` or `--port` is set;
- the app is not installed or does not open (prints install instructions);
- the daemon cannot start or speaks another protocol (prints why).

`servef browser [path]` always serves in a browser. On a machine without a
UI (an SSH session, or Linux without a display), `servef [path]` serves on
that machine's address and prints a `servef://` link for the app on your
computer ([Remote hosts](/docs/remote)).

## Links

`servef://local/?project=/abs/path` opens a project, and
`servef://local/view?…` takes the same query as a browser URL (`path`,
`wt`, `review`, …). Links never add directories; only `servef [path]` and
**File › Open Folder…** do. `servef walkthrough publish` prints a
`servef://` link when the app can show the walkthrough.

`servef://<host>:<port>/…` opens the servef server at that address: a
`localhost` address opens a [server in a terminal](#servers-in-a-terminal) on
this computer, any other host a [remote server](/docs/remote#links) over http
(the app asks first).

## Open folders from your file manager

Folders opened this way are added to the daemon, as `servef [path]` adds
them. Each folder's project opens in its own window (a window already
showing it comes forward), up to 8 folders at a time. A file, or a folder
servef cannot open, shows why.

### macOS

- Drop a folder on **servef** in the Dock or in Applications.
- From a terminal: `open -a servef ~/code/project`.
- For a Finder right-click entry, create a Quick Action once:
  1. Open **Automator**, choose **New Document**, then **Quick Action**.
  2. Set **Workflow receives current** to **folders** in **Finder**.
  3. Add **Run Shell Script**, set **Pass input** to **as arguments**, and
     replace the script with:

     ```sh
     open -a servef "$@"
     ```

  4. Save it as `Open in servef`. It appears under **Quick Actions** when you
     right-click a folder.

### Linux

The `.deb` adds **Open in servef** to the folder context menu in Dolphin
(KDE) and Nemo (Cinnamon). For other file managers, add an entry yourself.
With the AppImage, use its path instead of `servef-desktop`.

- Nautilus (GNOME Files): create
  `~/.local/share/nautilus/scripts/Open in servef`, make it executable
  (`chmod +x`), and pick it under **Scripts** when you right-click folders:

  ```sh
  #!/bin/sh
  exec servef-desktop --open-path "$@"
  ```

- Thunar: **Edit › Configure custom actions…**, add an action named
  `Open in servef` with the command `servef-desktop --open-path %F`, and
  check **Directories** under **Appearance Conditions**.

The deb does not make servef the default app for folders, so opening a
folder elsewhere never adds it to the daemon.

## Open at Login

Check **Open at Login** in the **servef** menu (macOS) or the **File** menu
(Linux) to start the app, with a window, when you log in. It is off until you
check it, and unchecking removes it.

- macOS adds servef to **System Settings › General › Login Items**. If macOS
  asks for approval, servef offers to open that page; allow servef there.
- Linux writes `~/.config/autostart/servef-desktop.desktop` (or under
  `$XDG_CONFIG_HOME`). For an AppImage it points at the AppImage file: after
  moving it, uncheck and check **Open at Login** again.

## Servers in a terminal

A server you start in a terminal (`servef browser`, or `servef` with
`--host` or `--port`) can open in the app too. **File › Connect…** lists the
servers running on this computer under **Servers on this computer**; click
one to open it in its own window, titled `… - localhost:<port>`.

To open a copied browser address, paste it into **Open a link** on the same
page. It accepts `http://localhost:<port>/…` (or `127.0.0.1`, `[::1]`)
addresses of a running servef server, and `servef://` links. Anything else
shows **Not a servef link**.

The app only shows such a server; it never starts or stops it, and sends no
notifications for it. When the server stops, its window says so: start it
again in the terminal and click **Retry**.

## Notifications

While the app runs it notifies for projects it has opened:

- **Switched to `<branch>`** and **New commit on `<branch>`**;
- **Edits settled**: changes stopped for 10 seconds;
- **Walkthrough ready**, for any project the daemon serves.

Clicking one opens the project, commit, changes, or walkthrough. Nothing is
shown for a project whose window is focused, and each kind repeats at most
every 30 seconds per project. Turn notifications off in your system settings.

## Uninstall

The uninstall script removes the app and CLI however you installed them in
your home directory: the install scripts, an AppImage you registered, the
desktop and login entries, the file manager actions, a Nautilus script or
Quick Action from the steps above, and `servef.app`. Quit the app and run
`servef daemon stop` first. It prints the command for the deb or a copy
another tool installed, and keeps your data:

```sh
curl -fsSL https://raw.githubusercontent.com/flexdinesh/servef/main/scripts/uninstall.sh | sh
```

By hand: uncheck **Open at Login** first, or remove servef from **Login Items**
(macOS) or delete `~/.config/autostart/servef-desktop.desktop` (Linux)
afterwards: uninstalling leaves it behind. Then quit the app and remove
`/Applications/servef.app` (macOS), or run `sudo apt remove servef-desktop`
(Linux). Remove any Quick Action, Nautilus script, or Thunar action you
created. App data lives in
`servef-desktop` under `~/Library/Application Support` or `~/.config`. The
daemon's remembered directories are in `servef/roots.json` in the same
place; `servef daemon stop` stops a running daemon.

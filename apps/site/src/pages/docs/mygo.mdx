# mygo app (experimental)

`servef-mygo` is an experiment: the same web UI as `servef browser` and the
[desktop app](/docs/desktop), in the operating system's web view through the
[mygo](https://github.com/egoist/mygo) toolkit instead of Electron's Chromium.
The desktop app stays the recommended app. Expect rough edges; things may
change or go away.

It shows projects on this computer, through the servef daemon. Context menus
and the menu bar come from the OS. Explorer, tabs, documents, diagrams, images,
and live updates have been tested in this app. Search, Source Control, code
navigation, and walkthroughs are the same UI, tested on WebKit in a browser but
not yet in this app.

Not in this app; use the desktop app for these:

- ssh connections and connecting to servef http servers. A
  `servef-mygo://<host>:<port>` link opens in your browser instead.
- Open at Login, notifications, recent folders, the Dock menu, and dropping
  folders on the window.

The page runs on WebKit: Safari's engine on macOS and WebKitGTK on Linux. A
distribution's WebKitGTK can lag behind what the UI is tested on. Known
differences from the desktop app:

- Text shifts slightly when a document gains a scrollbar.
- A review link to a line deep in a very large diff may not reach it.
- With no folder open yet, the window shows an error until you use File, Open
  Folder.

It has not been run on a Mac yet.

## Install

macOS and Linux, no sudo:

```sh
curl -fsSL https://raw.githubusercontent.com/flexdinesh/servef/main/scripts/install-mygo.sh | sh
```

Latest `main` (the `edge` prerelease; no macOS Intel builds):

```sh
curl -fsSL https://raw.githubusercontent.com/flexdinesh/servef/main/scripts/install-mygo-edge.sh | sh
```

Linux needs WebKitGTK 4.1 and GTK 3; the install script warns when it can't
find them. On Debian and Ubuntu:

```sh
sudo apt install libwebkit2gtk-4.1-0
```

The app carries its own `servef` binary for the daemon, so it needs no other
install. The scripts link `servef-mygo` into `~/.local/bin` (or `~/bin`).

- macOS: `servef-mygo.app` goes to `/Applications` (or `~/Applications`).
  Builds are ad-hoc signed, not notarized.
- Linux: the app goes to `~/.local/share/servef-mygo/app/`, with a desktop
  entry that opens `servef-mygo://` links and an icon.

Run a script again to update; quit the app first. Remove it with
`scripts/uninstall.sh`, which keeps its settings and page state: on Linux,
tabs and other page state stay in `~/.local/share/servef-mygo/`, beside the app.

## Use

```sh
servef-mygo .
```

opens the current directory. Only one copy runs: a second `servef-mygo`
command or link opens in the running app. The `servef` command never opens
this app.

Links use the `servef-mygo://` scheme:

- `servef-mygo://local/?project=/path/to/repo&path=README.md` opens a file
  through the daemon on this computer.
- `servef-mygo://<host>:<port>/?project=/path/to/repo` opens a servef server
  in your browser.

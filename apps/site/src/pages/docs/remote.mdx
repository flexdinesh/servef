# Remote hosts

servef runs beside the files. To browse another machine, serve it over http from
that machine and open its link in a browser. The [desktop app](/docs/desktop)
shows this computer's projects only: it has no ssh connections, and it opens
server links in your browser.

## Install servef on the host

Install the CLI on the remote machine as on any computer
([Getting started](/docs/getting-started)):

```sh
curl -fsSL https://raw.githubusercontent.com/flexdinesh/servef/main/scripts/install.sh | sh
```

The script needs no sudo and puts `servef` in `~/.local/bin` (or `~/bin`).
Release archives (`servef_<version>_linux_<amd64|arm64>.tar.gz`) work too;
put `servef` in `~/.local/bin`.

## Serve over http from the host

On a machine without a UI (inside an SSH session, or Linux without a
display), `servef [path]` serves in browser mode on the machine's own
address instead of opening anything:

```sh
servef ~/code/foo
```

```text
  servef 1.4.0
  serving directory:  /home/dee/code/foo
  web:      http://10.0.0.5:7971/
  desktop:  servef://10.0.0.5:7971/
  no authentication: anyone who can reach this address can read the served files.
```

Open the `web:` URL in a browser on your computer (terminals that support
hyperlinks make both clickable). The `desktop:` link does the same through the
desktop app, which hands it to your browser. The address is the server side of
your SSH connection, else the machine's outbound address; it binds that one
address, never all interfaces.

:::warning
These servers have **no authentication**. Anyone who can reach the address
can read the served files. Use them only on networks you trust. For a
private server, run `servef browser` (it binds `localhost`) and forward its
port yourself, for example `ssh -L 7971:localhost:7971 <host>`.
:::

`--host` and `--port` choose the address yourself. `servef browser` keeps
its `localhost` default everywhere and never opens anything over SSH.

## Walkthroughs

Agents on the host publish with `servef walkthrough publish`
([Walkthroughs](/docs/walkthroughs)). When a servef server on the host shows
the project, it prints the web URL and the `servef://` desktop link.
